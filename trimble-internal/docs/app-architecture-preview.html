2. Access & identity flow

sequenceDiagram
  participant User
  participant Hub as Hub index.html
  participant Gate as App access
  participant API as Apps Script
  participant Mail as Email

  User->>Hub: Open Technician Assistant
  Hub->>Gate: Show access gate
  User->>Gate: Submit work email
  Gate->>API: access_start

  alt @trimble.com auto-approve
    API-->>Gate: approved + session
  else External dealer email
    API->>Mail: Admin approval + sign-in code
    Mail-->>User: 6-digit code
    User->>Gate: Verify code
    API-->>Gate: approved + session
  end

  Gate-->>Hub: Unlock hub

  alt Trimble personnel @trimble.com
    Hub->>User: Show Internal master control in header
  else Dealer / partner email
    Hub->>User: Dealer hub only
  end

6. Feasibility summary

Difficulty: moderate — mostly wiring, not a rewrite. You already have email verification, @trimble.com auto-approve, session storage, and a hidden TMC pattern. This preview adds:

  • A personnel check (@trimble.com + valid app session)
  • Hub mode toggle (dealer vs internal) stored in sessionStorage
  • Category audience filtering in hub-nav.js
  • Path guards for internal-only tools
  • Header Internal master control (gold badge when active)

For production you can keep one GitHub Pages site (dealer tools only in deploy branch) or split deploy later. Internal tools stay out of dealer navigation until you flip trimbleInternalLocalPreview off and deploy with real @trimble.com sign-in.
